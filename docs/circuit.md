# 回路構成

master (Raspberry Pi Pico) 1台 + slave (RP2040-Zero) 最大8台 + アナログミキサーの実体配線図。
[VGM_multi_MCU_design.md](../VGM_multi_MCU_design.md) の構成方針をそのまま実装したもの。

| スレーブ#0 CS (SN76489) | GPIO12 | ソフトウェア制御CS |

| OLED SCL | GPIO1 | I2C0 SCL (同上) |

以前 GPIO0/1 は UART デバッグログ (TX/RX) に使っていましたが、ログは書き込み用USBケーブル経由の
USB CDC でそのまま見られる ([design-notes.md 8.1](design-notes.md#81-master)) ため、GPIO0/1 は
OLED 用の I2C0 に転用しました (`src/master/CMakeLists.txt` の `pico_enable_stdio_uart(master 0)`)。
物理 UART でもログを取りたい場合の戻し方は design-notes.md 8.1 を参照。

チップ⇔CS番号の対応、および各チップの有効/無効は **SDカードルートの `vgmplay.ini`** で
再ビルドなしに変更できます(次項 1.2)。既定値は `src/master/src/slave_bus.c` 冒頭のテーブル。
使わないチップを無効にすれば、そのVGMコマンドは静かに無視され、CS用GPIOも解放されます
(8スレーブ全部を同時に組む必要はなく、実際に使うVGMファイルが必要とするチップの分だけで十分)。
ログの見方は [design-notes.md](design-notes.md#8-ログの確認方法)参照。

### 1.1 OLED ステータス表示 (SSD1306, 任意)

再生中のファイル名・経過時間・使用チップ名を 128x64 の SSD1306 (I2C) に表示します。無くても
再生には一切影響しません (起動時に ACK が無ければ自動で無効化)。

| SSD1306 ピン | 接続先 (Pico) | 物理ピン番号 |
|---|---|---|
| GND | GND | 3番 (GPIO0/1 の隣) |
| VCC | 3V3(OUT) | 36番 |
| SCL | GPIO1 | 2番 |
| SDA | GPIO0 | 1番 |

- I2C アドレスは `0x3C` 前提 (`src/master/src/oled_ui.c` の `OLED_ADDR`)。`0x3D` の個体は書き換え。
- クロックは 400kHz。多くのモジュールは基板上に 4.7kΩ プルアップを持つのでそのままで動きます。
  無ければ SDA/SCL を 3V3 へ 4.7k〜10k で個別にプルアップ (ファーム側でも内蔵プルアップを有効化
  していますが弱いため)。
- 描画は **core1** が担当し、約23msかかる全画面転送を core0 の `wait_samples()` タイミングから
  切り離しています (再生テンポに影響させないため)。表示の更新は約150ms間隔。
- 経過時間はループ地点をまたいでも巻き戻らず加算され続けます (`vgm_player_elapsed_seconds()`)。

### 1.2 設定ファイル `vgmplay.ini` (任意)

SDカードのルート(.vgm/.vgz と同じ場所)に `vgmplay.ini` を置くと、**再ビルドなしで**チップごとの
有効/無効と CS ピンの GPIO 番号を変更できます。適用結果は起動時に USB CDC / UART ログへ出ます
(`slave bus: SN76489 cs=GPIO12 …`)。すぐ使えるひな形が `firmware/vgmplay.ini` にあります。

**ファイル名**: まず `vgmplay.ini` を探し、無ければ `vgmplay*.ini` にマッチする最初のファイル
(名前順、大小無視)を読みます。SDカードごとに搭載チップに合わせた設定を作るとき、
`vgmplay_scc.ini` `vgmplay_outrun.ini` のように名前で区別できて分かりやすいためです。
`vgmplay*.ini` が1つも無ければ `src/master/src/slave_bus.c` の既定値を使います。
(`vgmplay.ini` と `vgmplay_xxx.ini` の両方があるときは `vgmplay.ini` が優先。)

```ini
; チップ1種につき1セクション。キーは大文字小文字を区別しない。
[sn76489]
enabled = yes        ; yes/no/1/0/on/off/true/false
cs      = 12          ; このスレーブの CS を配線したマスター側 GPIO (0-28)
gap     = 40          ; 任意: 1バイトごとの CS パルス間隔 [µs](バイト欠落時に増やす)

[ym2151]
enabled = no          ; 無効にするとその VGM コマンドは無視され、CS用GPIOも解放
```

- `enabled = no` にしたチップ(またはそもそもスレーブを用意していないチップ)を**使う VGM/VGZ は
  再生されず自動でスキップ**されます(そのパートだけ欠けた状態で鳴らすのではなく、曲ごと飛ばす)。
  スキップ時は USB CDC ログに `skipping <名前> -- needs disabled/absent chip(s): <チップ名>` が出ます。
  カード内の全曲がスキップ対象だと `No playable songs` を表示して数秒おきに再スキャンします。

- セクション名は `-` `_` 空白と大小を無視: `[AY-3-8910]` `[ay8910]` `[Sega PCM]` はいずれも可。
  使える名前: `sn76489` `ym2413` `ym2612` `ay8910`(=`ay-3-8910`)`ym2151` `ym2203`
  `scc`(=`k051649`)`segapcm`。
- `;` または `#` で始まる行はコメント。行末コメントも可。
- `gap = 0` は **バースト転送**(3バイトを1回のCSで連続送信、バイトごとのパルス/待ちなし)。
  1フレームが約8倍速くなり、書き込みの密な曲でも master が追いつきます。ただし連続3バイトを
  確実にクロックインできる配線でのみ安全(初期のブリングアップ基板ではバイト2/3が落ちたため
  既定はバイトごとパルス)。パートがもたつく場合に試し、音の潰れ/ノイズが出たら戻してください。
- CS を `0-1`(OLED)`2`(スキップボタン)`10-11`(スレーブバス)`16-19`(SD)に割り当てると
  警告ログを出します(動作は続行)。範囲外(29以上)の値は無視。
- 書き換えたら SD を挿し直して電源再投入。
- テキストエディタで直接書けますが、GUI エディタもあります:
  `python3 tools/config_gui/vgmplay_config_gui.py`(Python 標準ライブラリのみ、
  [tools/config_gui/README.md](../tools/config_gui/README.md))。

## 2. スレーブ (RP2040-Zero) ピン割り当て

8種のスレーブファームウェアすべて同じピン配置です(スレーブ間でボードを使い回せます)。

| 機能 | GPIO | 備考 |
|---|---|---|
| SPI RX (マスターMOSIから) | GPIO8 | SPI1 RX |
| SPI CS (マスターから、個体ごとに配線) | GPIO9 | SPI1 CSn |
| SPI SCK (マスターから) | GPIO10 | SPI1 SCK |
| 音声出力 (PWM) | GPIO11 | 2段RC LPF経由でミキサーへ |
| デバッグログ TX | GPIO0 | UART0, 115200bps (任意、配線しなくても動作に支障なし) |
| デバッグログ RX | GPIO1 | 同上 (スレーブも受信は使わないので配線任意) |

RP2040-Zeroはピンヘッダに出ているのが GPIO0〜15 と GPIO26〜29 だけなので(GPIO16はオンボード
WS2812、17〜25/23〜25近辺は非公開)、スレーブのSPIは実機で配線できる GPIO8/9/10 (SPI1 グループ)
に割り当てています。GPIO0/1 はUARTログ、GPIO11 (SPI1 TX相当、このスレーブでは未使用) はPWM音声出力で、いずれもヘッダに出ています。
`gpio_set_function(pin, GPIO_FUNC_SPI)` は各ピン固有のSPI機能を選ぶため、GPIO8→SPI1 RX、
GPIO9→SPI1 CSn、GPIO10→SPI1 SCK となり、`slave_spi_rx_run()` には spi_index=1 を渡します
(`src/slave_*/src/main.c`)。マスター側(Raspberry Pi Pico、全ピン利用可)の配線は変更不要で、
変わるのはマスター⇔各スレーブ間の結線のスレーブ端だけです。ログの見方は
[design-notes.md §8.2](design-notes.md#82-スレーブ-rp2040-zero--pico)参照。

異なり、曲の頭でサンプルROMを一括アップロードしてから鳴らします(4章参照)。

## 4. Sega PCMスレーブについて (ROMアップロード)

Sega PCMは実機ではマスクROMにサンプルを持つ設計のため、他の7スレーブと違い曲の再生前に
サンプルデータをSPI経由でアップロードする必要があります。

- スレーブ側に約192KBの固定バッファを確保(1曲分のサンプルとしては十分すぎる程度。vgmrips.netの
  実例調査ではOut Run/Space Harrier/After Burner IIなどで1曲あたり20〜130KB程度)
- 曲の頭でVGMの`0x67`データブロック(type=0x80)を検出すると、マスターがそのブロック先頭8バイトの
  ヘッダ(全ROMサイズ+ROM内開始アドレス)を読み取り、`VGMSPI_OP_PCM_UPLOAD_RESET`で開始アドレスの
  256バイト境界へシーク→端数(`start & 0xFF`)を0x80(無音)で埋めてバイト単位に合わせてから、
  実データを1バイトずつSPIフレームで転送(`VGMSPI_OP_PCM_UPLOAD_BYTE`)。1曲のROMが複数ブロックに
  分かれていてもそれぞれ正しいアドレスに配置されます(密に詰めたripは開始アドレスが256の倍数で
  ないことがあり、以前はこのズレが連続ノイズになっていた)。1フレームごとにCSをパルスする方式(design-notes.md §2参照)のため1バイトあたり
  約65µsかかり、**曲の頭に数秒〜(192KBフルの場合)最大12〜13秒程度のロード時間**が発生します
  (実機のROM読み込みに近い体験として許容)
- **ROMウィンドウのリベース**: マスターは再生前に曲の全`0x67` type-0x80ブロックを事前スキャンし、
  最小開始アドレスを64KB単位に切り下げた値を`VGMSPI_OP_SEGAPCM_ROM_BASE`でスレーブへ通知。
  スレーブは以降すべてのサンプルアドレスからこのベースを引いてバッファに収めます。これにより、
  512KB級ROM(OutRun等)でサンプルがROM空間の上位(例:Magical Sound Showerは0x40000〜0x56000)に
  あっても、**曲が実際に使う範囲が192KB未満なら鳴ります**。ベースを引いてなお192KBを超える分、
  および範囲外アドレスは静かに切り捨て(クラッシュはしない)
- 曲頭でVGMヘッダ0x3C(Sega PCMインターフェースレジスタ)からバンク設定をデコードして
  `VGMSPI_OP_SEGAPCM_BANK`でスレーブへ転送。各chのCTRLレジスタ上位ビットのバンク番号で
  絶対ROMアドレスを再生します(上記リベース後の192KBウィンドウに収まる範囲まで。超過分は無音)
- アップロードに数秒かかるため、マスターは転送完了後に再生タイミングの基準時刻をリセットします
  (これをしないと曲が途中から始まったように聞こえる)
- 詳細は[design-notes.md](design-notes.md)参照

## 5. スレーブ1台分の音声出力段 (PWM → RCフィルタ)

PWMキャリアは sysclk/1024 ≈ 122kHz (10bit分解能)。2段RCで確実にキャリアを除去します。

```
GPIO11 (PWM, 0-3.3V) --[R 1kΩ]--+--[R 1kΩ]--+---> ミキサーの入力抵抗へ
                                |           |
                              [C 10nF]    [C 10nF]
                                |           |
                               GND         GND
```

fc ≈ 1/(2π×1k×10n) ≈ 16kHz。可聴帯域上限に近いですが -40dB/decade (2段)で122kHzキャリアは十分減衰します。
もう少しキャリア除去を優先したい場合は R=2.2kΩ, C=10nF (fc≈7.2kHz) に変更してください。

## 6. アナログ加算ミキサー (オペアンプ反転加算回路)

4スレーブ分をレールtoレール単電源オペアンプ1〜2個で加算し、DC成分をカップリングコンデンサで除去します。

```
                              Rf 10k
                        +----/\/\/\----+
                        |              |
 slave0 --[Cin 1µF]--[Rin 10k]--+      |
 slave1 --[Cin 1µF]--[Rin 10k]--+      |
 slave2 --[Cin 1µF]--[Rin 10k]--+--(-)\|
 slave3 --[Cin 1µF]--[Rin 10k]--+      >----+---> ミキサー出力 (Vref中心で振れる)
                                   (+)/
                                    |
                          Vref(=VCC/2): 10k+10k分圧 + 10µF以上でデカップリング
```

- 各スレーブのRC出力(5章)を **カップリングコンデンサ `Cin`(1µF程度)** → `Rin=10kΩ` 経由でオペアンプの
  反転入力ノードに接続。`Cin` を入れて交流だけ加算することで、各スレーブのRC出力DC中心(それぞれの
  VCC/2 ≈ 1.65V)と `Vref` の不一致による出力オフセットを防ぐ。`Cin`+`Rin` は fc ≈ 16Hz のHPFになる
- 帰還抵抗 `Rf=10kΩ` (Rin=Rfなら1入力あたりゲイン1倍。振り切れるようなら `Rf` を 6.8kΩ 等に下げる)
- **チップごとの音量差は、そのチップの `Rin` だけ変えて補正する**(各入力ゲインは `Rf/Rin` で独立。
  例: 小さく聞こえるチップの `Rin` を 10kΩ→5.6kΩ で約 +5dB)。ソースやファーム側のスケーリングは触らない
- 非反転入力には `VCC/2` の基準電圧 (抵抗分圧+デカップリングコンデンサ) を与え、単電源オペアンプでも
  ミキサー出力がレール中央に来るようにする
- **オペアンプは単電源(3.3V/5V)ならレールtoレール品を使う** (MCP6002 / TLV9002 / LMV358 等)。TL072 は
  本来両電源向けで、単電源だと出力がレール近くまで振れず入力同相範囲も狭い。TL072 を使うなら ±5〜±9V の
  両電源にし、その場合 `Vref` 回路は不要で非反転入力はGND直結
- 電源ピン直近に 0.1µF のパスコンを入れる
- ミキサー出力はDCブロック用コンデンサ (例: 1µF) を介してボリューム(10kΩ Aカーブ)→ヘッドホンアンプ
  (例: PAM8403 などの小型D級アンプIC) またはヘッドホンジャックへ

スレーブが1〜2台だけの構成なら、オペアンプなしで単純な抵抗混合(各出力からRin=2.2kΩ程度で1点に
まとめ、その先にDCブロックコンデンサのみ)でも実用上問題ない音量が得られます。3台以上は、出力どうしが
互いに負荷になってクロストークとレベル低下(概ね 1/N)が出るため、上記のオペアンプ加算を推奨。

## 7. 電源

- 各RP2040-Zeroはボード上のレギュレータでUSB 5V→3.3Vを生成するため、共有5Vバス(USBハブ経由、または
  5V電源+分配)から給電すれば個別レギュレータは不要
- マスターのPicoも同じ5Vバスから給電可(VBUSピン経由)。GND共通化を忘れないこと
- オペアンプ段は単電源(3.3V or 5V)＋レールtoレール品(MCP6002等)で動作させ、上記の`VCC/2`基準電圧回路で
  対応。両電源(±5〜±9V)にする場合は`VCC/2`回路不要で非反転入力はGND直結、TL072等も使用可

## 8. 部品表 (BOM)

対応チップは8種類 (SN76489 / YM2612 / AY-3-8910 / YM2413 / YM2151 / YM2203 / SCC / Sega PCM) ですが、
実際に組むスレーブ数 N は再生したいVGMファイルが使うチップの分だけで構いません。以下はN=4の例です
(N=8ならRP2040-Zero・RCフィルタ用部品・ミキサー入力抵抗をそれぞれ8に読み替え)。

| 部品 | 個数 (N=4の例) | 備考 |
|---|---|---|
| Raspberry Pi Pico | 1 | マスター |
| RP2040-Zero | N (例:4) | スレーブ、対応チップ8種から必要な分だけ選択 |
| microSD SPIモジュール | 1 | |
| 抵抗 1kΩ | 2N (例:8) | PWM用RCフィルタ (スレーブ1台につき2個) |
| コンデンサ 10nF | 2N (例:8) | 同上 |
| 抵抗 10kΩ | N+1 (例:5) | ミキサー入力N + 帰還1 (音量差のあるチップは入力側を個別に調整) |
| 抵抗 10kΩ | 2 | Vref (VCC/2) 分圧用 (両電源構成なら不要) |
| オペアンプ (MCP6002等の単電源RtoR品) | 1 | デュアルなら1個で足りる (もう1chは予備/ヘッドホンバッファに)。両電源ならTL072等 |
| コンデンサ 1µF | N+1 (例:5) | ミキサー各入力のカップリング N + 出力DCブロック 1 |
| コンデンサ 10µF | 1 | Vref デカップリング |
| コンデンサ 0.1µF | 1 | オペアンプ電源パスコン |
| ボリューム 10kΩ | 1 | |
| D級アンプIC (PAM8403等) or ヘッドホンジャック | 1 | |
| タクトスイッチ | 1 | 曲送りボタン (任意) |
| SSD1306 OLED (128x64, I2C) | 1 | ステータス表示 (任意)。1.1章参照 |

[VGM_multi_MCU_design.md](../VGM_multi_MCU_design.md) 通り、RP2040-Zeroは21×18mm程度なので、8台
フル構成+Pico+ミキサー基板でも手のひらに収まる程度のサイズです。
